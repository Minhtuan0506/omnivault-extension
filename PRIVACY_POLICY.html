Tiếng Việt

  • Mục đích duy nhất: Hỗ trợ người dùng lưu trữ, tự động điền mật khẩu, Passkeys (WebAuthn/FIDO2), sinh mã 2FA TOTP theo từng tên miền/subdomain chính xác, kiểm tra rò rỉ ẩn danh theo yêu cầu (opt-in) và tùy chọn đồng bộ mã hóa đầu-cuối (AES-256-GCM) với ứng dụng OmniVault.
  • Dữ liệu & Lưu trữ cục bộ: Tên miền trang web, tài khoản, mật khẩu, mã bí mật TOTP, thông tin Passkey và ghi chú do người dùng lưu được lưu trực tiếp trong chrome.storage.local. Ở Chế độ Cục bộ, không có bất kỳ dữ liệu kho mật khẩu nào rời khỏi trình duyệt.
  • Mã hóa khóa PIN: Khi người dùng đặt mã PIN, toàn bộ kho mật khẩu trong trình duyệt được mã hóa AES-256-GCM với khóa dẫn xuất PBKDF2-SHA256 (600.000 vòng, tự động nâng cấp tương thích ngược từ hồ sơ cũ 310.000 vòng); khóa phiên có hạn thời gian lưu tạm trong chrome.storage.session (gắn CryptoKey không trích xuất trong IndexedDB) và tự khóa sau 15 phút không thao tác hoặc khi máy rảnh/khóa màn hình.
  • Passkeys (WebAuthn / FIDO2): Khóa bí mật Passkey (P-256 PKCS#8) được sinh cục bộ trên thiết bị và lưu trữ chặt chẽ bên trong kho mã hóa đầu-cuối (E2EE) của người dùng; tuyệt đối không bao giờ gửi đi ở dạng chưa mã hóa.
  • Kiểm tra Lộ lọt Mật khẩu Ẩn danh Tùy chọn (Have I Been Pwned k-Anonymity): Hoàn toàn tự chọn (opt-in) — chỉ chạy khi người dùng chủ động bấm nút kiểm tra rò rỉ; chỉ gửi đúng 5 ký tự hex viết hoa đầu tiên của mã băm SHA-1 kèm tiêu đề Add-Padding: true tới api.pwnedpasswords.com. Mật khẩu gốc và mã băm đầy đủ không bao giờ rời khỏi thiết bị.
  • Sao lưu Ngoại tuyến .vlt Theo lịch (Android): Khi bật trên Android, bản sao lưu được ghi cục bộ vào thư mục SAF do người dùng tự chọn, mã hóa bằng Mật khẩu chính / Khóa khôi phục và không chứa bất kỳ siêu dữ liệu PIN nào (zero PIN metadata).
  • Đồng bộ đám mây (Tùy chọn): Chỉ khi người dùng chủ động dán mã kết nối OVB2-... (tương thích ngược với OVB1-...) từ điện thoại, dữ liệu mới được mã hóa hoàn toàn phía trình duyệt (Zero-Knowledge E2EE, HKDF-SHA256 + AES-256-GCM + AAD) trước khi gửi qua HTTPS.

English

  • Single Purpose: OmniVault provides strict domain/subdomain-isolated password and Passkey (WebAuthn/FIDO2) autofill, login capture with confirmation & undo, RFC-6238 TOTP 2FA code generation, opt-in anonymous breach auditing, and optional client-side end-to-end encrypted (AES-256-GCM) sync with the OmniVault mobile and desktop apps.
  • Local-First Storage: User-saved authentication items (domain, username, password, TOTP secret, Passkey material, notes) are stored locally on the device via chrome.storage.local (extension) or encrypted embedded redb storage protected by Argon2id + AES-256-GCM + Android Keystore TEE/StrongBox (Android app). In Standalone Local Mode, zero vault or user data is transmitted off-device.
  • Optional Client-Side Encryption & PIN Lock: Enabling PIN lock encrypts local vault data with AES-256-GCM using a PBKDF2-SHA256 (600,000 iterations, with seamless backward-compatible upgrade from legacy 310,000-iteration vaults) derived key stored transiently with expiration in chrome.storage.session (backed by a non-extractable WebCrypto CryptoKey in IndexedDB; 15-minute idle/sleep auto-lock).
  • Passkeys (WebAuthn / FIDO2): Private keys (P-256 PKCS#8) are generated locally on the device and stored strictly inside the user's E2EE vault; they are never transmitted unencrypted.
  • Optional Anonymous Breach Audit (Have I Been Pwned k-Anonymity): Strictly opt-in — runs ONLY when the user explicitly clicks the audit button; transmits ONLY the first 5 uppercase hex characters of the locally computed SHA-1 hash with Add-Padding: true to api.pwnedpasswords.com. Raw passwords and full hashes NEVER leave the device.
  • Scheduled Offline .vlt Backup (Android): Written strictly locally into the user-selected SAF folder, encrypted with the user's Master Password / Recovery Key, containing zero PIN metadata.
  • Optional Zero-Knowledge Sync: Only when paired by the user via an OVB2-... pairing code (backward-compatible with OVB1-...), encrypted HKDF-SHA256 + AES-256-GCM blobs are transmitted over HTTPS for cross-device sync.
  • Android Permissions (Strictly Opt-In & On-Device): Camera is accessed solely when the user scans a QR code (TOTP 2FA, VietQR EMVCo, or device pairing). Optional bank notification parsing (NotificationListenerService) is disabled by default, runs 100% locally on-device (sealed with X25519 while locked), and never transmits raw notifications externally.
  • Data Deletion & Contact: OmniVault requires no developer account. Users can permanently delete all local data anytime via Settings → Logout / Reset local data or by uninstalling the app, and can purge optional user-configured cloud ciphertext directly inside the app or by emailing mail@tuannguyenminh.com.
  • Read-Only Update Check (Zero User Data Sent): In standalone unpacked builds, the extension performs periodic read-only requests to GitHub Releases / GitHub Pages (Minhtuan0506/omnivault-extension) solely to check for newer extension releases. No user credentials, personal data, identifiers, or browsing history are ever transmitted. Chrome Web Store & Edge Add-ons packages strip nativeMessaging and update_url.
  • No Tracking & Limited Use Compliance: OmniVault collects zero browsing telemetry, serves no ads, sells no data, executes no remote code, and complies with the Chrome Web Store User Data Policy and Google Play User Data Policy.
